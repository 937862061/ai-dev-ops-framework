# 首次 AI 开发导览与本地状态协议

## 隔离范围与触发原则

每个本地开发者使用每个 AI 工具时，分别完成一次本项目导览。状态匹配“开发者 + AI 工具 + 项目标识”时，新会话、窗口、模型切换和工具重启均复用记录；换人或首次换工具必须独立导览。完成导览代表开发者已理解协作方式，AI 每次会话仍须按任务加载项目规范和知识。

- 工具使用稳定标识，如 `codex`、`claude-code`、`cursor`、`qoder`、`opencode`，不随会话或模型变化，不得借用其他工具标识。
- 开发者默认取当前操作系统账号。多人共用账号时，由开发者指定各自稳定的 `--developer <标识>` 或本地环境变量 `AI_DEV_OPS_DEVELOPER_ID`；后续操作保持一致，不取 Git 作者信息或会话 ID。
- 项目标识优先取 `origin`，没有 `origin` 且只有一个远程时取该远程，无远程才用仓库根绝对路径。多个远程且无 `origin` 时报告身份不明确，不擅自选择或退化成路径。
- 同域名、同仓库路径的 HTTPS、SSH、scp 地址去掉认证信息、尾部 `.git` 和默认 SSH 端口后复用；仓库路径大小写、非标准端口及 SSH Host 别名不擅自合并。远程变更或无远程项目迁移路径时，核实身份后再迁移旧记录。
- 普通知识库、代码和导览文字修订不自动撤销完成状态。仅开发者明确要求重新导览时才重置。

## 唯一查询入口

框架随项目维护 [scripts/onboarding_state.mjs](../scripts/onboarding_state.mjs)，使用 Node.js 18+ 标准库和本地 Git，不安装依赖、不联网、不写 Git 配置。接入项目时保留该位置，并将调用命令写入根入口和 knowledge skill，不能只要求 AI “记住”。

每个新会话在检索当前需求事实前必须运行 `check`。以下 `codex` 仅适用于 Codex，其他工具替换为自身稳定标识；命令从项目根运行，其他工作目录使用脚本绝对路径与 `--repo <项目目录>`。

```powershell
node .agents/skills/ai-dev-ops-framework/scripts/onboarding_state.mjs check --tool codex --repo .

# 仅在明确确认或核实本身份旧本地确认记录后登记；随后回查。
node .agents/skills/ai-dev-ops-framework/scripts/onboarding_state.mjs complete --tool codex --repo . --confirmed
node .agents/skills/ai-dev-ops-framework/scripts/onboarding_state.mjs check --tool codex --repo .

# 仅在开发者明确要求重新导览时执行。
node .agents/skills/ai-dev-ops-framework/scripts/onboarding_state.mjs reset --tool codex --repo .
```

共用系统账号时，每条命令追加相同的 `--developer <个人标识>`，或使用本地环境变量；不得把个人身份参数配置进项目共享文件。`complete --confirmed` 只登记已存在的确认事实，不授权 AI 自行确认；“开始开发”、P0/P1/P2 完成及无明确确认的旧聊天均不能作为依据。

命令输出单份 JSON，按 `status` 分流，不能把非零退出码一律解释为首次使用。输出含匹配身份及 `stateFile`，用于核对真实查询位置；不将实际个人状态输出另存到仓库、共享文档或项目日志。

| status | 退出码 | 必须执行的行为 |
|---|---|---|
| `COMPLETED` | 0 | 静默跳过导览，不读取、复述正文或重复确认；按任务加载项目规范 |
| `MISSING` | 10 | 仅核实本身份旧本地确认记录，有依据才迁移，无依据才首次导览 |
| `REQUIRED` | 10 | 按要求重新导览并等待确认；禁止迁回旧记录 |
| `ERROR` | 20 | 报告并处理环境、权限、身份或格式错误，不能当作已完成或未完成，不自动重做导览 |

`check` 只读，不创建目录。`complete` 原子替换文件并回读校验，重复登记已完成记录不改变时间。`reset` 写入待确认记录，防止删除后又从旧记忆迁回。明确确认后必须再次 `check` 成功，才开始需求分析；无法持久化时如实说明，不用仓库标记替代。

## 固定存储与隐私边界

```text
<操作系统用户资料目录>/.ai-dev-ops/onboarding/<开发者哈希>/<工具标识>/<项目哈希>.json
```

脚本通过操作系统账号信息解析真实用户资料目录，不使用沙箱可能改写的 `HOME`、`LOCALAPPDATA`，避免不同会话落入不同临时目录。解析真实路径后拒绝工作区、任何 Git 仓库（含 worktree）内的状态位置，不提供命令行目录覆盖选项。

记录仅含协议版本、完成或待确认状态、开发者、工具、项目标识与登记时间。`recordedAt` 表示本次登记时间，迁移时不冒充原人工确认时间。状态不属于项目资产，不进入 Git、Git 配置、数据库、共享文档或日志；规则、脚本与不含真实个人状态的测试才随项目维护。

固定目录不依赖模型是否自动检索记忆，不跨开发者或工具同步。多人共用系统账号时，开发者标识只解决查询隔离，不构成操作系统访问权限隔离。

## 旧本地确认记录迁移

仅 `MISSING` 时允许迁移：检查当前工具已经提供的本地持久记忆或已知本地记录，核实当前开发者、当前工具、同一项目以及明确确认过的事实。记录不完整不得猜测，更不能从其他工具或项目计划继承。

有明确匹配依据时，以当前身份执行 `complete --confirmed` 并回查，不重复展示导览；保留原记录，不复制到项目或其他工具。迁移只是将同一确认事实放入固定位置。`REQUIRED` 表示用户后来已要求重做，不能再次从旧记录迁入。

## 导览阶段允许的动作

确认前仅允许读取本协议、执行本地状态查询、核对上述旧记录及读取目标项目导览正文。项目身份所需的本地 Git 元数据读取属于查询的一部分，不读取 Git 历史或业务配置。

确认前不得按当前需求检索知识库、代码、配置、表结构、接口、日志、Git 历史或外部资料，也不得输出需求分析、概念确认清单、实施方案，修改代码、修复数据或发起外部操作。

导览说明项目入口、skill、知识库和代码事实的分工，按事实定位、有歧义时提问与概念确认、高风险操作责任、静态验证与未验证项及知识保鲜义务。明确确认后登记完成，再进入当前任务。

## 接入和验收

根 `AGENTS.md` 与 knowledge skill 必须同时要求执行固定查询并链接本协议；不支持原生根入口的工具，在其项目入口引用 `AGENTS.md`。只声明“工具会记住”不能作为验收。

基础协议由项目入口要求 AI 执行，不预设各版本都支持启动 hook。另行配置 hook 时只调用同一只读查询，不能启动即登记完成；按各工具输出协议适配，验证启动、恢复及权限失败。没有实际安装、信任配置和新会话验证时，不报告 hook 已生效。

```powershell
node --test .agents/skills/ai-dev-ops-framework/scripts/onboarding_state.test.mjs
```

行为验证覆盖首次查询只读、确认后独立进程复用、换人/换工具/换项目、同远程不同克隆与协议、无远程回退、损坏记录与读取失败、重新导览及拒绝仓库内状态。测试只用仓库外临时目录；P0-P2 进度不代替个人导览记录。
