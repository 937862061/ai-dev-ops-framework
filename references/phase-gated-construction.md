# 分阶段建设流程

本流程确保调用 skill 后从 P0 逐步建设，而不是一次生成空泛文档后宣称完成。阶段状态记录在 `ai-knowledge/plan/ai-dev-ops-plan.md`；除首次创建 P0 骨架外，必须先读取该文件再决定下一步。

## P0：建立入口并等待确认

首次调用且计划不存在时，只能创建下列骨架，不得检索目标项目代码、配置、表、日志、接口、外部资料或既有业务知识：

- 根 `AGENTS.md`；
- `ai-knowledge/readme.md`、`ai-knowledge/ai-development-onboarding.md`；
- `ai-knowledge/PRD/`、`plan/`、`system/`、`ops/` 目录；
- `ai-knowledge/plan/ai-dev-ops-plan.md`，记录 P0 范围、权威来源、目录职责、阶段状态和待确认项。

P0 交付时说明已建立内容、尚未检索的项目事实，并请开发者明确确认“确认 P0，已阅读导览，可以开始 P1”。然后**结束当前轮**。未获得确认前，不得实施 P1 或 P2。

## P1：事实盘点与详细系统文档，并等待确认

收到 P0 确认后，按 [详细系统文档规范](detailed-system-documentation.md) 盘点并写入目标项目事实。先完成架构与全量模块索引，再按业务域补齐数据和主链路；发现歧义时先提问，不能以猜测补齐。

P1 结束时更新计划文件，列出：已覆盖模块/领域/表/链路、每项证据锚点、未覆盖项及原因、待开发者确认的业务问题。请开发者明确确认“确认 P1，可以开始 P2”，然后**结束当前轮**。

## P2：接入项目 skill，并完成基线

收到 P1 确认后，创建或完善 knowledge、dev-spec、ops 三类项目 skill，更新根 `AGENTS.md`、知识库入口和加载矩阵，使其指向 P1 生成的真实文档。逐项执行 P2 验收并在计划文件中记录结果。

P2 完成后报告“P0-P2 基线体系已完成”、验收证据、未核实事实和未执行验证。此时必需体系完成；不得将未执行的 P3/P4 标记为失败或自行启动它们。

## P3/P4：仅按需继续

- P3：开发者提供真实需求后，验证知识检索、概念确认、定位、修改与知识保鲜的完整闭环。
- P4：根据开发者要求，建立定期治理、质量复核或推广机制。

## 计划文件最小结构

```markdown
# <项目名> AI 开发运维体系实施计划

## 当前状态
- 当前阶段：P0 / P1 / P2 / P3 / P4
- 状态：进行中 / 待开发者确认 / 已完成
- 最近确认：<日期、确认内容>

## P0 决策与待确认项
## P1 覆盖矩阵与事实缺口
## P2 接入与验收记录
## P3/P4（按需）
## 未执行验证与风险
```

计划文件记录过程与状态，不替代 `system/` 和 `ops/` 中已经核实的长期事实。
